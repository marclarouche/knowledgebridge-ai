# User guide

Knowledge Collections creates, opens, renames and deletes saved collections. Empty collections persist. Document Import saves extracted source records immediately; default limits are 10 MiB per file and 100 documents per collection. Original uploads are not retained. Duplicate byte content within a collection is skipped. The application never overwrites an original source file.

Index and Search builds the active index from saved library sources. Pending imports survive restart but are not searchable until a successful build. The index status distinguishes not_indexed, indexed, stale (saved sources differ from active search) and failed (index inconsistency). Reindex selected document uses current chunk settings on retained sections and rebuilds the active snapshot, preserving any separate pending imports.

Document Library lists saved documents and their source/version/hash metadata. Replace selected document validates the uploaded replacement and, for indexed collections, builds the complete replacement index before activation. A failed parse, limit check, model request or database transaction leaves the old source searchable. A successful replacement rebuild also includes pending library imports. Identical bytes and unchanged metadata are a no-op; a changed version produces new passage IDs even if the bytes are unchanged.

Deleting a document removes it from the saved library and active retrieval. The remaining active embeddings are reused without Ollama. Pending imports remain saved and pending. Removing the last indexed document removes the active index; the saved collection remains available for future imports. Collection deletion removes that collection's sources and active index. Deletion controls require confirmation specific to the displayed source revision. A stale form cannot overwrite another session's changes; reload and review the current selection when a conflict is reported.

Lifecycle operations clean obsolete keyword/vector generations after committing the active change. If cleanup fails, the library change remains active and a warning requests retry via Clean obsolete index generations in Settings and Diagnostics. Backups, filesystem/database remnants and transient session memory are outside a secure-erasure guarantee.

Source Explorer browses the active indexed documents and exact passages or resolves a passage ID. Inspect source below an answer opens its cited quote with complete passage context, document title, version, filename, section, page and offsets. Old generation references and removed/replaced passage IDs are explicitly marked outdated; they are not silently redirected to a new document. A retained latest answer also warns when its index is superseded. Parsed Documents and Passage Explorer continue to inspect saved pending sources before indexing.

Ask KnowledgeBridge uses the last active indexed snapshot. Citation and same-model support checks can miss errors; verify important claims in the originals. Missing evidence, unsupported/invalid drafts and local service failures produce withholding statuses. Confirmed conflicts show source versions without choosing authority from recency. CPU-only inference may be slow; generation defaults to a 240-second socket timeout per request. There is no disk conversation history; only the latest answer remains in session memory for source navigation.

Settings and Diagnostics displays bounded configuration and cleanup controls. Edit config/knowledgebridge.yaml for subsequent import, chunking, retrieval and model settings. Embedding model changes require rebuilding; generation model changes do not alter stored embeddings. Keep original files because retained extracted sections cannot recover content omitted during parsing. DOCX table layout, PDF reading order, comments, tracked changes and images are limited; scanned PDFs require external OCR.
